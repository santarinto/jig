# Как портал потребляет `@santarinto/jig`

Источник правды для миграции портала `santarinto/site` (`frontend-react/`) на дизайн-систему
**`@santarinto/jig`**. Документ самодостаточный: по нему можно работать, не открывая исходники DS.

Текущая версия пакета — **1.0.0**. Стек потребителя: React 19 + TypeScript + Vite.

---

## 1. Поставка

Пакет **не публикуется в npm-реестр**. Канал — готовый тарбол на GitHub Release
репозитория `santarinto/jig`. На каждый тег `vX.Y.Z` GitHub Actions собирает `dist/`,
пакует его тем же `npm pack`, каким это делает разработчик, и прикладывает
`santarinto-jig-X.Y.Z.tgz` к релизу этого тега (`.github/workflows/release.yml`).

Репозиторий **публичный, ставится анонимно** — без ключа, без токена, без доступа по
приглашению. Никакой отдельной приватности и переговоров об access не осталось: адрес
работает у кого угодно, кто может достучаться до `github.com`.

Ставьте по адресу конкретного релиза — правки одной версии в `package.json` без
переустановки недостаточно, потому что версия зашита в самом URL, а не разрешается по
имени пакета:

```bash
npm install --save '@santarinto/jig@https://github.com/santarinto/jig/releases/download/v1.0.0/santarinto-jig-1.0.0.tgz'
node -p "require('./node_modules/@santarinto/jig/package.json').version"   # → 4.2.6
```

Для другого релиза замените `4.2.6` на нужную версию **в обоих местах** URL — в сегменте
тега (`vX.Y.Z`) и в имени файла (`santarinto-jig-X.Y.Z.tgz`). Это не два независимых места:
CI резолвит ассет по тегу, и если версии разойдутся, отдаст 404 или чужой файл под
похожим на верный адресом — гейт `install-url` в DS держит их совпадающими в этом самом
документе.

**Установка НИЧЕГО не собирает и не качает лишнего.** Ассет — уже готовый `dist/`,
упакованный тем же `npm pack`, каким его собрал бы себе кто угодно; lifecycle-скриптов у
пакета нет вовсе (`files: ["dist", "README.md"]`), и `npm ci` в чистом чекауте только
скачивает тарбол по URL и распаковывает его. Ни клонирования репозитория, ни
`devDependencies` design-системы (18 пакетов и её собственный `tsc`) при установке не
происходит — тарбол несёт ровно то, что в `files`.

Строка с `node -p` — не формальность: `package-lock.json` хранит `resolved` с тем же URL,
что стоит в `package.json`, и явная переустановка после смены версии — единственный
надёжный способ убедиться, что лок действительно сдвинулся, а не остался версией
предыдущего копирования зависимости. За это в DS отвечает гейт `npm run smoke:upgrade`: он
пакует два последних локальных тега **своими worktree**, тем же `npm run tarball`, каким
собирает релиз CI, и сверяет, что версия в `node_modules` после переустановки
действительно сдвинулась — не кодом выхода, а фактом. Что тег `vX.Y.Z` **вообще лежит на
GitHub** с приложенным и не битым ассетом, стережёт отдельный гейт — `make published`: он
единственный трогает сеть, поэтому не входит ни в `check`, ни в `check-full`.

Затем — `CHANGELOG.md` дизайн-системы на ломающие изменения.

## 2. Что импортировать

```tsx
// компоненты — только из корня пакета
import { Button, TextField, DataTable, Modal, Badge } from '@santarinto/jig'

// стили — ОДИН раз в точке входа приложения (main.tsx)
import '@santarinto/jig/styles.css'

// шрифт Inter — тоже один раз, если не подключён иначе
import '@santarinto/jig/fonts/inter.css'
```

Доступные подпути экспорта:

| Подпуть | Что это |
|---|---|
| `@santarinto/jig` | все компоненты, типы, `tokens`, `cssVar`, theme API (`setTheme` / `useTheme` / `ThemeToggle`) |
| `@santarinto/jig/styles.css` | **единственная** точка входа стилей: токены + CSS всех компонентов |
| `@santarinto/jig/tokens/tokens.css` | только токены, без стилей компонентов (нужно редко) |
| `@santarinto/jig/fonts/inter.css` | `@font-face` для Inter (400/500/600/700) |
| `@santarinto/jig/fonts/Inter-*.woff2` | сами файлы шрифта |

**Шрифт поставляется пакетом.** Четыре `.woff2` (~460 KB суммарно) лежат внутри тарбола;
Vite подхватит их как ассеты. Ставить Inter отдельно не нужно. Если в портале уже есть свой
Inter — не импортируйте `@santarinto/jig/fonts/inter.css`, чтобы не грузить шрифт дважды.

## 3. Размер интерфейса — `--ds-ui-scale`

Вся метрика (типографика, высоты контролов, отступы) задана в `rem` и умножается на
`--ds-ui-scale`. Это даёт две вещи сразу: интерфейс уважает настройку размера шрифта в браузере
(DS больше не переопределяет корневой `font-size`), и портал может дать пользователю свой регулятор.

```ts
document.documentElement.style.setProperty('--ds-ui-scale', '1.15')
```

> **На корневом элементе (`<html>`) — просто переменная; на контейнере — переменная И класс
> `.ds-scale`.** Метрические токены объявлены в `:root`, и `var(--ds-ui-scale)` внутри их `calc()`
> вычисляется там же, где токен объявлен. Голая переменная на контейнере отмасштабирует только
> покомпонентные `calc()`, а токены останутся единицей — получатся растянутые строки с прежним
> размером текста. Проверено замером: на обёртке высота строки 30px → 39px, а шрифт остаётся 14px.

### Масштаб одного поддерева — `.ds-scale`

Когда корня нет под рукой (виджет в чужом кадре, встроенная панель), нужный размер задаётся классом
вместе с переменной:

```html
<div class="ds-scale" style="--ds-ui-scale: 1.25"> … </div>
```

Класс объявляет **все** метрические токены заново на этом элементе — там `var(--ds-ui-scale)` и
вычисляется, поэтому поддерево едет целиком. Без класса переменная делает половину работы, и это
хуже, чем ничего: своими руками переобъявленные «три токена из восемнадцати» разваливают компонент
по швам — высота и шрифт вырастают, горизонтальные отступы и мелкие подписи остаются.

Масштабы **не перемножаются**: вложенный `.ds-scale` считает от базового размера, а не от
родительской шкалы. `1.5` означает полтора, где бы элемент ни стоял.

Разумный диапазон — `1` … `1.4`. Волосяные границы (1–2px) и радиусы намеренно **не** масштабируются:
растянутая линия замыливается, а раздутые скругления перестают читаться как фирменный почерк
системы.

## 4. Тема

Светлая по умолчанию. Публичное API (волна 2 / B2):

```tsx
import { initTheme, setTheme, getTheme, useTheme, ThemeToggle } from '@santarinto/jig'

initTheme()          // при старте: localStorage, иначе prefers-color-scheme
setTheme('dark')     // записать выбор и выставить data-theme на <html>
getTheme()           // 'light' | 'dark'

function Header() {
  const [theme, setTheme] = useTheme()
  return <ThemeToggle />
}
```

`setTheme` ставит `data-theme` (`"light"` или `"dark"`) на `document.documentElement` и помнит
выбор в `localStorage` (ключ `ds-theme`). Модуль безопасен без DOM (SSR/тесты).

**С 1.38.0 светлая — тоже атрибут, а не его отсутствие.** «Атрибута нет» теперь значит «выбор не
сделан», и это ровно условие, по которому работает `theme-auto.css` (§4.1). До 1.38.0
`setTheme('light')` атрибут снимал, и у пользователя, явно выбравшего светлую на машине с
системной тёмной, страница становилась тёмной — выбор отменялся тем самым файлом, который обещает
обратное. **Если у вас есть свой boot-скрипт, снимающий атрибут для светлой, — поставьте
`data-theme="light"` вместо `removeAttribute`**, иначе тот же дефект останется у вас.
Все цвета переключаются через токены — руками ничего перекрашивать не нужно.

Низкоуровневый обход (редко нужен): `document.documentElement.setAttribute('data-theme', 'dark')`.

### 4.1. Тема без клиентского JS

`initTheme()` и `ThemeToggle` требуют работающего JS в браузере. Если его нет вовсе (SSR-страница,
отдаваемая одним GET), есть два пути, и они складываются.

**Системная тема, ноль JS — `theme-auto.css` (с 1.37.0).** Подключается **явно**, рядом со
`styles.css`:

```html
<link rel="stylesheet" href="/ds/styles.bundle.css">
<link rel="stylesheet" href="/ds/theme-auto.css">
```

Внутри — те же тёмные токены под `@media (prefers-color-scheme: dark)` со скоупом
`:root:not([data-theme])`. Скоуп обязателен и не косметический: **явно поставленный атрибут
побеждает системный**, а не спорит с ним; без `:not(...)` медиазапрос и атрибут оказались бы
одного веса и решал бы порядок файлов. Файл генерируется из `tokens.css` при сборке, и гейт
сверяет состав и значения токенов — два ручных списка одних цветов разъезжаются.

**Почему не по умолчанию:** приложение, не звавшее `initTheme()`, сегодня на машине с системной
тёмной рисуется светлым. Медиазапрос в `tokens.css` перекрасил бы всех существующих потребителей
при ближайшем бампе — молча, потому что это цвет, а не типы.

**Ручной выбор — инлайновый скрипт в `<head>`, до ссылки на стили** (иначе первая отрисовка
успевает пройти в светлой и видна вспышка):

```html
<script>
(function () {
  try {
    var stored = localStorage.getItem('ds-theme');
    var theme = (stored === 'light' || stored === 'dark') ? stored
      : (matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light');
    if (theme === 'dark') document.documentElement.setAttribute('data-theme', 'dark');
  } catch (e) { /* приватный режим Safari: localStorage бросает на чтении */ }
})();
</script>
```

Это логика `initTheme()`, свёрнутая до синхронно исполнимого. Ключ хранилища тот же — `ds-theme`,
и это не деталь: добавите потом настоящий `ThemeToggle` — он подхватит выбор, а не начнёт свою
историю. Тёмная — атрибут, светлая — его отсутствие (`data-theme="light"` закрыл бы путь
`theme-auto.css`, который весь построен на «атрибута нет»).

## 5. Версии peer-зависимостей

```json
"peerDependencies": {
  "react": "^19",
  "react-dom": "^19"
}
```

React **не входит** в пакет — берётся из портала. Это принципиально: как обычная зависимость
он привёл бы ко второй копии React в `node_modules` и падению хуков.

**React 18 больше не поддерживается** (DS-104). Раньше peer объявлял оба конца
диапазона, и оба проверялись отдельным прогоном. Держать два рантайма — значит держать два
поведения, в которых дефект может жить порознь; вдобавок проверялся второй конец лишь
наполовину, рантаймом, тогда как типы оставались 18-ми, и переезд это сразу показал
(`useRef` без аргумента в `NumberField` — ошибка компиляции на `@types/react@19`, которую
прежний дубль не видел по устройству).

Потребителю на React 18 установка теперь ОТКАЖЕТ, а не деградирует: `npm install` упрётся
в `ERESOLVE could not resolve` на peer-зависимости. Своя версия проверяется так:

```bash
node -p "require('./node_modules/react/package.json').version"
```

Разработка DS идёт против той же версии, что стоит у потребителя, — отдельного прогона
для второй больше нет, потому что второй версии нет.

**Проверка после установки** — копия React должна быть ровно одна:

```bash
find node_modules -path '*node_modules/react/package.json' \
  -not -path '*/node_modules/*/node_modules/*' | wc -l   # → 1
```

## 6. Стилизация своей вёрстки

Компоненты самостилизованы, оборачивать их ни во что не нужно — никакого провайдера в DS нет.
Для собственной вёрстки (сетки, отступы, свои блоки) используйте токены, **никогда не хардкодьте
цвет**: иначе тёмная тема его не переключит.

```tsx
<div style={{
  display: 'flex',
  gap: 'var(--ds-space-3)',
  background: 'var(--ds-surface)',
  border: '1px solid var(--ds-border)',
  color: 'var(--ds-text-primary)',
}} />
```

Основные семейства токенов (полный список — в `dist/tokens/tokens.css` внутри пакета):

- **Цвет:** `--ds-accent` (+`-hover`/`-active`), `--ds-bg-app`, `--ds-surface`, `--ds-surface-subtle`,
  `--ds-section-bar`, `--ds-border`, `--ds-border-strong`, `--ds-text-primary`/`-secondary`/`-muted`,
  `--ds-text-on-accent`, `--ds-success`/`--ds-warning`/`--ds-error`/`--ds-info`, `--ds-overlay`
- **Типографика:** `--ds-font-ui` (Inter), `--ds-fs-sm`…`--ds-fs-2xl` (база `--ds-fs-base` = 14px при `--ds-ui-scale: 1`)
- **Метрика:** `--ds-space-1`…`--ds-space-8` (шаг 4px), `--ds-radius-sm`/`--ds-radius`/`--ds-radius-md`,
  высоты контролов `--ds-h-compact` (28px) / `--ds-h-default` (32px) / `--ds-h-comfortable` (36px).
  Все они в `rem` и умножаются на `--ds-ui-scale` — см. раздел 3

Система плотная: предпочитайте `size="sm"`, небольшие отступы, короткие подписи.

### Классы `ds-*` — не публичный контракт

Токены, имена компонентов и их пропсы — контракт, который держится между версиями. **Имена классов
внутри компонента — нет.** Они меняются без объявления в `CHANGELOG`: в 1.22.0 блок `CodeBlock`
переименовался из `.ds-code` в `.ds-codeblock`, потому что столкнулся с `CodeInput`, и это была
починка, а не изменение API.

Практический вывод один: **не пишите тесты, которые ищут элемент по классу `ds-*`.** Ищите по роли и
доступному имени — `getByRole('tab', { name: 'В работе 7' })`. Такой тест переживёт наше
переименование и заодно проверяет то, что важно: что вкладка называется так, как её слышит человек.

Со стилями то же самое: цепляться к `.ds-tabs__count`, чтобы что-то подкрасить, можно, но это связь
с нашими внутренностями. Если такой стиль нужен постоянно — скажите, и мы сделаем это пропом.

### Коробка: DS всегда `border-box` (с 1.7.0)

Начиная с 1.7.0 пакет сам объявляет `box-sizing: border-box` на своих элементах — на всём, что
несёт класс с префиксом `ds-`. Настраивать ничего не нужно, и **никакого reset'а от вас не
требуется**: DS считается одинаково и под Tailwind preflight, и в приложении без единого
глобального правила.

Что это значит на практике:

- Высоты `--ds-h-compact` (28) / `--ds-h-default` (32) / `--ds-h-comfortable` (36) — это
  **видимые** высоты, вместе с рамкой. Выравнивая свою вёрстку по контролу DS, берите токен как
  есть, ничего к нему не прибавляя.
- Правило скоупится по префиксу, а не по `.ds-root`, поэтому компонент, отрисованный мимо
  обёртки, имеет ту же геометрию. Обёртка нужна для другого — см. «Своё правило `body`».
- **Ваша вёрстка внутри `.ds-root` не затронута.** Если у приложения нет своего reset'а, ваш
  `<div style={{width: 100, padding: 10}}>` останется 122px шириной, как и был. DS отвечает
  за свои элементы, не за соседей.

Если вы поднимаетесь с 1.6.x **без** глобального reset'а, интерфейс станет на 1–2px плотнее в
местах, где рамка раньше добавлялась поверх объявленной высоты: `Badge` 20 → 18px, ячейки
`MetricStrip`, пилюли, шапки. Это выравнивание к объявленным значениям, а не новая плотность —
подробности и полный список в `CHANGELOG.md`, раздел 1.7.0. Если reset у вас уже есть (Tailwind,
shadcn, normalize с `*`), вы не увидите ничего: эта геометрия у вас была и до 1.7.0.

Отменить модель на своём элементе можно обычным правилом — специфичность (0,1,0) у обоих,
побеждает подключённый позже.

### DataTable: своё правило `padding-left` для ячеек гасит отступ по глубине

Отступ по уровню дерева (`flattenTree`) держится на том же свойстве `padding-left`, что и
базовый падинг ячейки, и с тем же весом — намеренно, чтобы `.ds-table td { padding-left: … }`,
подключённое после стилей DS, могло его перебить. Плата: такое правило гасит отступ по глубине
целиком, а не только базовый падинг — все уровни дерева получат один и тот же `padding-left`.
Если нужен и свой падинг, и рабочая иерархия, учитывайте `--ds-row-depth` в своём правиле
(переменная уже лежит на первой ячейке строки), а не задавайте фиксированное число.

## 7. Что есть в пакете (89 экспортов-значений)

**Формы:** `TextField`, `Textarea`, `NumberField`, `Select`, `Combobox`, `DatePicker`, `Calendar`,
`Checkbox`, `Radio`, `Switch`, `Slider`, `CodeInput`, `FileDrop`, `FormRow`, `FormTabs`

**Действия и навигация:** `Button`, `CommandBar`, `DropdownMenu`, `AppBar`, `Breadcrumbs`, `Tabs`,
`Pagination`, `SectionPanel`, `FunctionPanel`, `GlobalSearch`, `SearchBar`, `SideNav`

**Данные:** `DataTable`, `LedgerList`, `LineChart`, `BarChart`, `DonutChart`, `Stat`, `Dashboard`, `Tile`, `Card`, `Badge`, `Skeleton`,
`EmptyState`

**Числа в отчёте:** `Money` (сумма строкой из БД: знак, эквивалент, «данных нет»), `AsOf` (возраст
числа — «остаток на 07.08.2026», порог устаревания), `EstimateMark` (звёздочка оценочности — и у
суммы, и у процентной ставки), `OrgBadge` (значок организации: логотип, монограмма, «не опознана»)

**Модель строк для `DataTable`:** `flattenTree(nodes, getRowId, expandedIds)` —
иерархия справочника; `groupByValue(rows, getRowId, key, expandedKeys, formatLabel?, options?)` —
группировка по значению колонки. `options` — `{ summarize?, aside? }`: `summarize(rows)` даёт
итог под колонками (`group.cells`), `aside(value, rows)` — узел справа в шапке группы. Обе —
чистые функции: состояние раскрытия держит приложение и передаёт обратно пропсом `displayRows`,
компонент своего состояния не заводит.

**Колонки `DataTable` — два вида.** `DataColumn` стоит за полем строки (`key: keyof T`), это форма
из всех прежних версий. `DisplayColumn` поля не имеет — прогресс из двух чисел, кнопки действий,
иконка состояния:

```tsx
const columns: Column<Line>[] = [
  { key: 'name', header: 'Номенклатура' },
  { id: 'actions', header: '', render: (r) => <Button onClick={() => open(r.id)}>Открыть</Button> },
]
```

Свойство называется `id`, а не `key`, намеренно: опечатка в настоящем ключе (`nmae`) остаётся
ошибкой типов, а не превращается в валидную колонку, рисующую пустоту. `render` у `DisplayColumn`
обязателен. `sortable` разрешён — сортируете вы, мы только зовём `onSort(id)`.

**Подсветить активную строку без чекбоксов** — `selectedIds` без `onToggleRow`:

```tsx
<DataTable columns={cols} rows={rows} getRowId={(r) => r.id}
  selectedIds={[activeId]} onRowClick={(r) => setActiveId(r.id)} />
```

Колонка выбора появляется **только** вместе с `onToggleRow`. Один `selectedIds` даёт строке класс
`is-selected` и фон `--ds-table-selected` — ровно то, что нужно, когда клик по строке открывает
деталь в соседней панели и надо показать, какая строка открыта.

Имя пропа звучит как «множественный выбор с галочками», поэтому этот случай легко не заметить —
отсюда пример.

**Оговорка при пагинации.** `selectedIds` сверяется только со строками текущей страницы. Если
выбранная запись живёт в общем списке, а на экран выдана страница без неё, подсветки не будет ни на
одной строке — при том что деталь справа продолжает показывать запись. «Выбор есть, но он не на этой
странице» и «выбора нет» выглядят одинаково, и таблица различить их не может: она видит только
переданные ей строки. Решать это приходится приложению — например, показывать в панели, что запись
с другой страницы.

**Скрытие колонки, когда таблице тесно** — `hideBelow: 'sm' | 'md'`:

```tsx
{ key: 'updatedAt', header: 'Обновлена', hideBelow: 'md' }
```

Порог считается от **ширины самой таблицы**, а не вьюпорта. Причина практическая: таблица в узкой
боковой панели на широком мониторе при медиазапросе не спрятала бы ничего, и это выглядело бы как
«`hideBelow` не работает».

Скрытая колонка **отдаёт свою ширину оставшимся**, а не оставляет пустое место: прячется трек
вместе с ячейками. Замер на обёртке 400px с колонками 100/100/100/остаток — после скрытия второй
колонка-остаток берёт 199px вместо 100.

Из нижней границы ширины таблицы скрытая колонка тоже выходит, поэтому `hideBelow` — рабочий
ответ и на «таблица вылезла за обёртку». Замер: обёртка 342px, ширины 192+80+120 и колонка без
ширины; со скрытой второй таблица встаёт в 376px вместо 456.

Пороги — `40em` (≈520px) и `56em` (≈728px) при масштабе 1, и они едут вместе с `--ds-ui-scale`:
при 1.25 в ту же ширину влезает меньше содержимого, значит прятать пора раньше. Сырые пиксели были
бы единственной частью таблицы, игнорирующей масштаб.

**Таблица теперь завёрнута в `<div class="ds-table-wrap">`** — это контейнер запроса. Без обёртки
не обойтись: `container-type` на самой `<table>` попадает в computed style, но запрос по нему не
срабатывает (проверено в chromium). Если ваши стили адресуют таблицу как **прямого** потомка
(`.panel > table`), поправьте на `.panel table` — селекторы по потомкам не затронуты. Липкая шапка
обёртку переживает, проверено замером.

**Типизируйте `columns`, а не полагайтесь на вывод из `rows`.** `T` выводится из `rows`, и на
`rows={[]}` — первый рендер до загрузки — схлопывается в `never`, после чего `getRowId` перестаёт
типизироваться с невнятной ошибкой. `const columns: Column<Line>[] = …` снимает это: `T` берётся
из колонок.

### Итог группы и строка-итог

```tsx
import { DataTable, groupByValue } from '@santarinto/jig'

const displayRows = groupByValue(ops, (o) => o.id, 'day', expanded, formatDay, {
  // Итог под колонкой: значение — узел, можно мульти-валюту
  summarize: (rows) => ({ amount: <Money list={sumByCurrency(rows)} /> }),
  // Или произвольный узел справа в шапке дня (два итога + приписка)
  aside: (_day, rows) => (
    <span className="feed-day__totals">
      <Totals label="потрачено" totals={spent(rows)} />
      <Totals label="поступило" totals={received(rows)} />
      <span>{excludedNote(rows)}</span>
    </span>
  ),
})

<DataTable columns={cols} displayRows={displayRows} onToggleExpand={toggle}
  footer={{ label: 'Всего', cells: { amount: <Money list={grandTotal} /> } }} />
```

Значение в `cells`/`footer.cells` — **`ReactNode`, не число**: итог дня может быть массивом сумм по
валютам (RUB/KZT без общего курса). Компонент ничего не суммирует — значения приходят готовыми.
`footer` рендерится в `<tfoot>`; `cells` проецируются под свои колонки тем же выравниванием
(numeric, tnum, hideBelow), что и ячейки данных.

### Приглушённая строка

```tsx
<DataTable columns={cols} rows={ops} getRowId={(o) => o.id}
  rowState={(o) => ({ muted: o.ownTransfer || o.declined })} />
```

`muted` приглушает **текст** строки (`--ds-row-muted-fg`), подложку не трогает вовсе.
Раньше было наоборот — подложка `--ds-surface-subtle`, — и в тёмной теме знак
переворачивался: та подложка светлее строки (#2E2E2E против #262626), то есть
приглушённая запись выходила ЗАМЕТНЕЕ обычной. Тон текста держит 4.5:1 на всех четырёх
подложках строки (обычной, зебре, наведении, выборе) в обеих темах.

Число без знака/цвета делается в ячейке суммы (`<Money signed={false} tone="muted" />`),
не классом: CSS знак «−» убрать не может.

### Вычёркивание отклонённой строки — в вашем `render`

Компонент черту на строку не вешает (флага `voided` намеренно нет). Отклонённую операцию
вычеркните в `render` колонки описания, а пояснение выведите **из-под черты** —
`text-decoration` предка потомок не снимает, поэтому узлу нужен свой контекст декорации
(`display: inline-block`):

```tsx
render: (o) => (
  <span style={{ textDecoration: o.declined ? 'line-through' : undefined }}>
    {title(o)}
    {o.declined && (
      <span style={{ display: 'inline-block', textDecoration: 'none' }}> · отклонена</span>
    )}
  </span>
)
```

### LedgerList — раскрываемая лента без JS

Лента/выписка, которая рендерится статически (без гидрации): раскрытие строки —
нативный `<details>`, переключает браузер. Это **отдельный компонент**, не режим
`DataTable`: `<details>` невалиден внутри `<table>`.

```tsx
import { LedgerList, groupByValue } from '@santarinto/jig'

const displayRows = groupByValue(ops, (o) => o.id, 'day', expanded, formatDay, {
  aside: (_day, rows) => <DayTotals rows={rows} />,
})

<LedgerList
  columns={cols}
  displayRows={displayRows}
  rowState={(o) => ({ muted: o.ownTransfer || o.declined })}
  hasDetails={(o) => hasDetails(o)}
  renderExpanded={(o) => <OpDetails op={o} />}
  footer={{ label: 'Итого за период', cells: { sum: <Money list={grandTotal} /> } }}
/>
```

Запись раскрывается, только если `renderExpanded` вернул не-`null` (и `hasDetails`
не вернул `false`) — стрелка не рисуется в пустоту. Раскрытие работает **без
вашего состояния**; `defaultOpenIds` открывает записи в статике. `muted` красит
только фон; вычёркивание отклонённой — в вашем `renderExpanded`/колонке (как в
DataTable, приём с выходом «· отклонена» из-под черты). Колонки сводки
выравниваются между строками сами (CSS subgrid) — задавать ширины не обязательно.

**У `LedgerList` нет `hideBelow` у колонок** (в отличие от `DataTable`).
Раскладка на CSS Grid + `subgrid`, и `display: none` на ячейке оставляет трек
дыркой (трек задан в `grid-template-columns` корня и скрытием ячейки не убирается)
— остальные ячейки сдвигаются, и это выглядит как испорченные данные. Поэтому
поля в типе `LedgerColumn` нет намеренно: заданный и молча игнорируемый проп —
хуже ошибки типов. Узким экраном управляют `width` колонок: `minmax(0, 190px)`
счёту/категории, `minmax(18ch, 1fr)` описанию — единственный тянущийся трек
забирает свободное место, числовые держат ширину.

**Каретка раскрываемой записи (`▸`) стоит на ведущей ячейке и сдвигает её
содержимое вправо на ~14px.** Это следствие конструкции (каретка — `::before` на
ведущей, не отдельный трек — иначе она заняла бы колонку), не дефект: у
нераскрываемой записи этого отступа нет, и левые края расходятся. Выравнивайте
ведущую колонку вправо (или подпись ведущей — `text-align: right`), и правые
краи сумм сходятся ровно по subgrid.

**Тело вкладок — `TabPanel`.** Вкладки соединяются с обведённой панелью в один виджет:

```tsx
<Tabs id="history" tabs={tabs} activeId={id} onSelect={setId} />
<TabPanel tabsId="history" activeId={id} noPadding>
  <DataTable … />
</TabPanel>
```

`id` у `Tabs` и `tabsId` у панели — **один и тот же**: из него собираются связи (`aria-controls` на
вкладках, `aria-labelledby` на панели). Без `id` у `Tabs` вкладки не получат DOM-идентификаторов, и
панель сошлётся в пустоту.

`noPadding` — под содержимое со своими краями (`DataTable` рисует строки от границы до границы).
Для графика или текста паддинг нужен, поэтому по умолчанию он есть.

Панель фокусируема: её содержимое может не иметь ни одного управляемого элемента, и иначе до него
не добраться с клавиатуры.

**Заодно исправлено в самой полосе:** неактивные вкладки теперь имеют нижнюю границу. Раньше каждая
вкладка закрашивала линию полосы своим фоном — без тела это было незаметно, а с телом неактивные
выглядели бы «открытыми» в него наравне с активной.

**Значок статуса на вкладке** — `Tab.icon`:

```tsx
<Tabs activeId={id} onSelect={setId} tabs={[
  { id: 'todo', label: 'В работе', icon: <DotIcon />, count: 7 },
  { id: 'done', label: 'Готово', count: 0 },
]} />
```

Значок **декоративен**: он `aria-hidden` и в доступное имя вкладки не попадает. `count`, наоборот,
попадает — число записей иначе не узнать, а смысл статуса обязан нести текст подписи. Отсюда
правило: если значок сообщает то, чего нет в подписи, — это не значок, а подпись, и переписать надо
её.

**KPI-плитка и блок команды:**

```tsx
<Stat label="За последний час" value={12} unit="commits/hour"
      adornment={<Badge tone="success">новый коммит</Badge>}
      delta={{ value: 3, direction: 'up' }} />

<CodeBlock code={'php bin/console app:tracker:task:add portal "…"'} />
```

`unit` — отдельный проп: значение набрано `--ds-fs-2xl` весом 600, и единица строкой получила бы тот
же кегль. `adornment` — **статус**, а не действие: он читается слитно с подписью («за последний час,
новый коммит»), поэтому фокусируемую кнопку туда класть нельзя.

`CodeBlock` — только чтение, горизонтальная прокрутка, кнопка копирования. Подсветки синтаксиса нет
намеренно; если она нужна, передайте готовую разметку в `children` — копируется всегда `code`.
`CodeInput` к этому отношения не имеет, это поле ввода одноразового кода.

Моноширинный шрифт вынесен в токен `--ds-font-mono` — им набраны и `LogViewer`, и `CodeBlock`.

**Присутствие на аватаре и зелёная кнопка запуска:**

```tsx
<Avatar name="ai-worker-3" presence="online" />
<Button variant="success">Старт</Button>
```

`Button` — `size`: `'sm' | 'md' | 'lg'` (`--ds-h-compact` / `--ds-h-default` / `--ds-h-comfortable`).

Кольцо присутствия — `online` / `busy` / `away` / `offline`. Состояние попадает **в доступное имя**
(«ai-worker-3, в сети»), а не только в цвет; `presenceLabel` меняет слово. «Не в сети» — нейтральное
кольцо, а не его отсутствие: пустота означала бы «состояние неизвестно».

Кольцо нарисовано тенью и размер аватара не меняет — карточка не дёргается при смене состояния.

`variant="success"` — для действия, которое **запускает** («Старт», «Выкатить»), а не для «сохранено»:
сообщение об успехе это `Alert`, а кнопка говорит, что произойдёт.

**Кнопка-ссылка для навигации без JS** — `as="a"`:

```tsx
<Button as="a" href="/" variant="ghost">Обновить</Button>
<Button as="a" href="/debts" variant="secondary">Долги</Button>
```

Рендерит `<a class="ds-btn">` вместо `<button>`: переход работает без гидрации (на
статических страницах, где `<button>` без JS мертва). Союз дискриминирован по `as`:
при `as="a"` обязателен `href` (строка), доступны только якорные атрибуты (`target`,
`rel`, …). `type`/`form`/кнопочный `onClick` при `as="a"` дают **ошибку типов**, а не
деградацию — нельзя случайно уронить кнопочное поле на `<a>`. `disabled` и `loading`
на ссылке превращаются в `aria-disabled` + `tabIndex={-1}` (нативного `disabled` у
`<a>` нет). Второй механизм отдать свой элемент — `renderItem` у `SideNav`/`Tabs`/
`Breadcrumbs` — для коллекций; у одиночной кнопки коллекции нет.

**Подвал таблицы — `Pagination`.** Селектор размера слева, диапазон по центру, навигация справа:

```tsx
<Pagination
  page={page} pageCount={pages} onChange={setPage}
  variant="arrows"
  total={total} pageSize={size}
  pageSizeOptions={[8, 25, 50]} onPageSizeChange={setSize}
/>
```

Даёт «На странице [20] … 21–40 из 347 … ‹ ›». Метку меняет `formatRange` целиком, а не по слову:
`formatRange={(f, t, n) => \`${f}–${t} of ${n}\`}`.

Полоса сама несёт вертикальный и горизонтальный паддинг и отделяется рамкой сверху — **своих
отступов добавлять не нужно.** Стоящая сразу за `<DataTable>` полоса свою рамку не рисует: у
таблицы уже есть нижняя, и две соседние дали бы линию в два пикселя.

**Прежняя форма не тронута.** Без `total`/`pageSizeOptions` это ровно тот же inline-блок с
номерами и кнопками «Назад»/«Вперёд», что и раньше, — и геометрия совпадает до пикселя (замерено:
портал использует его так в трёх местах).

Одно изменение затрагивает и прежнюю форму: **полоса номеров теперь сворачивается** — первая,
последняя, текущая и соседи, между ними многоточие. До этого рисовалась кнопка на каждую страницу:
на 10 000 записей по 20 — пятьсот кнопок. Заметно это только там, где страниц больше семи.

**Слои и уведомления:** `Modal`, `Drawer`, `Popover`, `Tooltip`, `Accordion`, `Alert`, `Toast`,
`Toaster`, `NotificationCenter` + императивный API `toast.success/error/warning/info(text)`,
`dismissToast(id)`, `clearToasts()`

**Тема:** `ThemeToggle`, `initTheme`, `setTheme`, `getTheme`, `useTheme`, `subscribeTheme`

**Графики:** `chartSeriesVar(i)` / `chartSeriesVars` / `CHART_SERIES_COUNT` — палитра серий
(`--ds-chart-1`…`--ds-chart-8`), общая для `LineChart`, `BarChart` и `DonutChart`

**Прочее:** `tokens`, `cssVar`, готовые экраны-примеры `DocumentFormExample`, `WorkspaceExample`

### Своё правило `body` перебивает наше — ставьте `ds-root`

`tokens.css` объявляет на `body`: `font-family`, `font-size`, `line-height`, `color`,
`background`. Если у приложения есть собственное правило `body` (например
`body { @apply bg-background text-foreground }`), оно побеждает — селектор тот же, а таблица
подключается позже. Наследуемым остаётся **чужой `color`**: крупные цифры, часы, значения
берут его и на светлой поверхности DS становятся почти невидимыми. Ни сборка, ни тесты об этом
не скажут.

Лечится классом на корне экрана — он весит (0,1,0) против (0,0,1) у `body`:

```tsx
<div className="ds-root">
  {/* весь экран на DS */}
</div>
```

Проверено замером: без класса текст наследует чужой `color`, с классом — `--ds-text-primary`.

**Корень экрана — это корень экрана, а не любой контейнер.** `.ds-root` задаёт и
`background: var(--ds-bg-app)`, поэтому надетый на что-то внутри страницы он красит фоном
**приложения** кусок, который таковым не является. Внутри `Card` это видно сразу:

```
светлая:  .ds-root #F0F0F0  внутри карточки #FFFFFF
тёмная:   .ds-root #1A1A1A  внутри карточки #262626
```

Замерено `getComputedStyle` (потребитель, DS-55: обёртку надели вокруг
своего компонента внутри нашей `Card`). Одна обёртка на экран — и всё; вложенным компонентам
она не нужна, потому что **геометрия от неё не зависит**: `box-sizing` скоупится по префиксу
`[class^="ds-"]`, а не по `.ds-root` (см. «Коробка» выше). Если вашей вёрстке внутри карточки
не хватает нашего `color`, берите токен напрямую (`color: var(--ds-text-primary)`), а не
обёртку.

### Календарь внутри карточки

`.ds-cal` — самостоятельная панель: своя рамка, тень, отступ, `inline-block`. Внутри `Card` это
рамка в рамке. Проп `embedded` снимает всё это и делает календарь шириной по месту:

```tsx
<Card title="Тренировки" subtitle="июль 2026">
  <Calendar year={2026} month={6} months={3} readOnly embedded />
</Card>
```

В мультимесячном режиме общий заголовок больше не рисуется: каждая панель подписана сама, и
якорный месяц подписывался дважды подряд.

### Метрики на узком экране

`MetricStrip` по умолчанию держит все метрики в одну строку. Проп `columns` (2, 3 или 4)
переносит их, а ячейка, оставшаяся одна в последнем ряду, занимает ряд целиком — иначе рядом
с ней зияет дорожка цвета сетки:

```tsx
<MetricStrip metrics={metrics} columns={2} />
```

Число колонок здесь явное, а не выведенное из ширины. `repeat(auto-fit, minmax(...))` даёт
перенос без пропа, но растянуть одинокую ячейку при этом нечем: `auto-fit` схлопывает только
полностью пустые дорожки, а `nth-child` не принимает переменную. Проверено замером — три
метрики в две колонки оставляли третью шириной 159px из 320.

### Шапка карточки в две строки

`Card` берёт две строки двумя способами. Заголовок с подписью — `title` + `subtitle`.
Длинный заголовок в два ряда вместо многоточия — `titleLines={2}`; больше двух рядов не
бывает, иначе шапка растянется на всю карточку.

```tsx
<Card title="Время" subtitle="часовые пояса">…</Card>
<Card title="Спорт · последняя тренировка за период" titleLines={2}>…</Card>
```

Шапка виджета больше не имеет жёсткой высоты: она растёт под содержимое, а однострочный
случай остаётся прежним (замер: 40.86px до и после).

**Графики и доступность.** `LineChart`, `BarChart` и `DonutChart` всегда объявлены как
`role="img"` с именем: передайте `ariaLabel`, если есть осмысленное, иначе компонент соберёт имя
из подписей своих серий или долей. Отдельно ничего отключать и прятать не нужно.

Точные пропсы каждого компонента — в его `.d.ts` внутри пакета
(`node_modules/@santarinto/jig/dist/src/components/<Name>/<Name>.d.ts`).

### Важно про типы

`.d.ts` перечисляет **только собственные пропсы** компонента. Часть компонентов дополнительно
принимает нативные HTML-атрибуты (`value`, `onChange`, `placeholder`, `disabled`, `name`,
`required`, `maxLength`…), даже если в `.d.ts` их не видно:

`TextField`, `Textarea`, `Select`, `Checkbox`, `Radio`, `Switch`, `Button`, `Badge`, `Card`,
`AppBar`, `CommandBar`.

Исключения: у `TextField`/`Textarea`/`Select` проп `size` — свой (`"sm" | "md"`), не HTML'ный;
`SearchBar` сам управляет `value`/`onChange`. Компоненты вне списка (`NumberField`, `Combobox`,
`DatePicker`, `DataTable`…) принимают ровно то, что в их `.d.ts`.

### `Alert` или `Card tone`? — разные инструменты, не разная громкость

Оба показывают состояние тоном, и их легко перепутать. Граница практическая:

| | что это | как выглядит |
|---|---|---|
| `Alert` | **сообщение о событии** | заливка 12% + полоса слева, иконка тона |
| `Card` + `tone` | **состояние контейнера**, содержимое обычное | полоса 3px сверху, заливки нет |

«Задача заблокирована» **карточкой в списке задач** — это `tone`: пользователь
смотрит на список и должен различить состояния, не читая каждую.

«Задача заблокирована» **уведомлением вверху экрана** — это `Alert`: сообщение
адресовано пользователю здесь и сейчас.

Признак, по которому их машинно не спутать: у тонированной карточки **нет
заливки**. Это закреплено инвариантом в `npm run measure`.

### LogViewer: `getLineId` обязателен — рабочий пример

Проп не имеет значения по умолчанию намеренно. Единственный дефолт, доступный компоненту, —
индекс в массиве, а индекс ломается ровно там, где проп и нужен: при подгрузке старых записей
вверх все строки сдвигаются, ключи разъезжаются, окно теряет опору и прокрутка прыгает.

Форма, доехавшая до продакшена у потребителя (лента диалога ИИ-воркеров, `ai.dialog`):

```ts
const getLineId = (l: AiDialogEntry) => `${l.runId}:${l.seq}`
```

`seq` — монотонный порядковый номер строки в разрезе `(worker, run_id)`, а курсор пагинации
составной: `(ts, seq) < (X, S)`.

**Почему не по одному `ts`.** Изначально там сортировали и листали по `ts`, а он неуникален:
шиппер пишет строки пачками, и несколько строк ложатся в одну миллисекунду. Курсор `ts < X`
при этом **теряет данные**: строки с граничным `ts`, не поместившиеся в страницу, не вернёт ни
один запрос. Тот же разрез ломает и синтетический ключ вида `ts + '#' + индекс-внутри-ts` —
индекс детерминирован только при полной пачке.

Мораль для любого потребителя: ключ строки обязан быть уникальным **по построению**, а не по
рассуждению о том, что коллизий не бывает.

## 8. Навигация и роутер — шов `renderItem`

`Tabs`, `Breadcrumbs` и `SideNav` не знают про роутер и не должны. Шов `renderItem` **подменяет**
элемент: DS отдаёт пропсы, потребитель раскладывает их на свою ссылку, и она сама становится
вкладкой, крошкой или пунктом.

```tsx
<Tabs
  tabs={tabs}
  activeId={activeId}
  renderItem={(tab, props) => <Link to={`/mail/${tab.id}`} {...props} />}
/>
```

Один интерактивный элемент, один таб-стоп, валидный HTML; средний клик, «открыть в новой вкладке»
и префетч роутера работают нативно, потому что это настоящая ссылка, а не кнопка рядом с ней.

**Оборачивать не нужно, и до 1.17.0 `SideNav` требовал именно этого — неправильно.** Прежний шов
отдавал готовую `<button>` и документировал `<Link>{inner}</Link>`, то есть давал `<a><button>`.
Замер: **два таб-стопа на один пункт** вместо одного, и на каждом втором скринридер объявлял
элемент, который никуда не ведёт. Если у вас в коде остался вид `(item, inner) => <Link>{inner}</Link>`
— это старая сигнатура, меняйте на `(item, props) => <Link {...props} />`.

**Два места, где шов намеренно не срабатывает.** Ветка с детьми в `SideNav` остаётся кнопкой: она
раскрывает поддерево, а не ведёт по ссылке. Последняя крошка в `Breadcrumbs` — текущая страница, и
ссылкой на саму себя быть не должна. В обоих случаях `renderItem` просто не вызывается, и это
проверено тестами.

`onSelect` остаётся: он нужен, когда состояние ведёт не роутер (сабтабы внутри диалога), и
вызывается и со швом, и без него.

Типы пропсов экспортируются — `TabRenderProps`, `CrumbRenderProps`, `SideNavRenderProps` — если
раскладку нужно передать в свой компонент-обёртку.

## 9. Требования к сборке (важно)

Пакет **рассчитан на бандлер** — Vite, webpack, Next и т.п. Компоненты импортируют свой CSS
(`import './Button.css'`), а нативный ESM-резолвер Node такое не грузит. Для приложения портала
это не ограничение: Vite и так собирает всё. Потребление **без** сборщика тоже поддерживается —
см. §9.1.

**Но у vitest в портале это всплывёт.** Vitest по умолчанию externalizes зависимости и резолвит
их Node'ом — тест, импортирующий компонент DS, упадёт на `Unknown file extension ".css"`.
Лечится инлайном зависимости:

```ts
// vitest.config.ts портала
export default defineConfig({
  test: {
    server: { deps: { inline: ['@santarinto/jig'] } },
  },
})
```

Спецификаторы внутри пакета — с явными расширениями (`./Button.js`, `./components/Button/index.js`),
так что резолвинг модулей у Node проблем не вызывает; упирается всё только в CSS.

### 9.1. Потребление БЕЗ сборщика (SSR в голом Node)

Поддерживается с 1.37.0 и проверяется целью `smoke-ssr` (рендер в строку, установка из тарбола,
сверка классов `ds-*` в выдаче). До 1.37.0 сценарий работал, но не проверялся ничем.

Компоненты рендерятся в статический HTML на сервере, клиентского JS не нужно ни строки.
Единственное препятствие — `import './Button.css'`: это **след сборки, а не механика**. JS про
стили ничего не знает, они целиком в классах `ds-*`. Поэтому пустой модуль на `.css` не обходит
поведение — он точно описывает то, чем этот импорт и является.

```js
// css-hook.js — подключается через --import
import { registerHooks } from 'node:module'
registerHooks({
  load(url, ctx, next) {
    if (url.endsWith('.css')) return { format: 'module', source: 'export default undefined;', shortCircuit: true }
    return next(url, ctx)
  },
})
```

```
node --import ./css-hook.js server.js
```

**CSS подключается отдельным `<link>`, и брать надо плоский файл:**

```html
<link rel="stylesheet" href="/ds/styles.bundle.css">   <!-- @santarinto/jig/styles.bundle.css -->
<link rel="stylesheet" href="/ds/fonts/inter.css">
<link rel="stylesheet" href="/ds/fonts/mono.css">
<link rel="stylesheet" href="/ds/theme-auto.css">      <!-- по желанию, см. §4 -->
```

`styles.css` — это 62 `@import`. Сборщику они ничего не стоят, а для `<link>` в браузере это 62
последовательных запроса и требование раздавать всё дерево `dist/src` статикой (потребитель
замерил на живой странице: 65 запросов). `styles.bundle.css` — тот же CSS одним файлом, в том же
порядке; порядок значим, часть каскада решается им, а не весом селектора.

**Что не работает без гидрации.** Компонент, держащий состояние в `useState`, на сервере всегда в
начальном состоянии, а обработчиков нет вовсе. Отдельно опасны те, где разметка при этом выглядит
рабочей:

| Берите смело | Выглядит кликабельным, но мертво |
|---|---|
| `Card`, `Badge`, `Alert`, `Stat`, `MetricStrip`, `KeyValueList`, `ProgressBar`, `EmptyState`, `Timeline`, `Breadcrumbs`, `CodeBlock`, `AppBar`, `CommandBar` | `DataTable` с `sortable` — заголовок рендерит `<button>` и `aria-sort="none"` |
| Графики: SVG считается при рендере, `viewBox` фиксирован | `DataTable` с раскрытием строк |
| `Heatmap` — подсказка нативным `title`, единственная в системе, что переживает отсутствие гидрации | `Combobox`, `DropdownMenu`, `Popover`, `DatePicker`, `Accordion`, `Tabs`, `Tree`, `FileDrop`, `LogViewer`, `SideNav` — панель существует только в открытом состоянии |
| `DataTable` **без** `sortable` и без раскрытия | `NumberField` (шаговые кнопки), `Pagination`, `ThemeToggle` |

Тему ставьте атрибутом на сервере или подключите `theme-auto.css` (§4) — `ThemeToggle` без
гидрации мёртв.

### 9.2. Кэш статики: версию — в адрес, безверсионный адрес — убрать

Если раздаёте `dist` сами (как портал и ещё один потребитель), ставьте версию пакета в **адрес**
статики — `/ds/X.Y.Z/styles.bundle.css`, а не `/ds/styles.bundle.css`. Иначе кэш переживёт
следующий бамп: браузер держит бандл, собранный до обновления, и `max-age` секунд отдаёт старые
стили под тем же адресом.

**Ловушка не в кэше, а в том, как она выглядит.** После бампа `npm test` зелёный, `curl` на
`/ds/styles.bundle.css` отдаёт правильный файл со всеми правилами, а страница сломана: новый
компонент приезжает без стилей, маркированным списком синих ссылок. Все автоматические проверки
говорят «всё хорошо», поэтому первым под подозрение попадает новый компонент DS, а не кэш. Это тот
же класс, что дефект git-установки до 1.6.1: об успехе сообщено при неуспешном результате.

**Безверсионный адрес не дополняйте версией, а убирайте.** Оставить `/ds/styles.bundle.css`
рабочим «ради совместимости» — вернуть ту же болезнь: кэш снова живёт под ключом, который ни о чём
не говорит. Пусть и безверсионный адрес, и чужая версия отдают 404 — тихий 200 по старому адресу не
виден вовсе, а 404 виден сразу.

**Шрифты версионируются сами — руками их трогать не надо.** `fonts/*.css` ссылаются на `.woff2`
относительными `url('./Inter-Regular.woff2')`, поэтому браузер подставляет версию из адреса самой
таблицы стилей: подключили `/ds/X.Y.Z/fonts/inter.css` — и `.woff2` уедут на `/ds/X.Y.Z/fonts/…`
сами (проверено на живой странице: шесть файлов, все 200).

**`max-age` можно поднимать хоть до года с `immutable` — но ровно пока тег версии означает
неизменные байты.** У пакета теги неподвижны: `vX.Y.Z` не передвигается на месте. Если же тег
когда-нибудь сдвинуть, потребитель будет держать старое не час, а год, — поэтому условие стоит
проговорить, а не подразумевать.

## 10. Чеклист миграции экрана

1. Убрать импорты shadcn/ui-примитивов, заменить на компоненты `@santarinto/jig`.
2. Убрать Tailwind-классы, отвечавшие за цвет/типографику/радиусы, — это теперь работа DS.
   Утилиты раскладки (flex/grid/отступы) можно оставить или перевести на инлайн-стили с токенами.
3. Проверить оба режима темы (светлый и `data-theme="dark"`).
4. Ни одного хардкод-цвета в новом коде.
5. Прогнать сборку портала: `npm run build`.
